## Changes from the prior handoff

The v3 migration removes the writable `preregistration_proven` authority field and replaces it with audit-chain proof. It adds composite lineage foreign keys, `run_config_hash`, observation-protocol identity, database-generated validation eligibility, a lifecycle event state machine, benchmark drift tables, and stricter primitive/R1 promotion gates.

The verifier no longer validates only fills + final NAV. It compares orders, fills, marks, positions, cash, and equity and first checks each stream against an independently reconstructed spot-accounting state.

The probe plan was normalized to explicit 1-minute UTC 24/7 input conventions and no longer uses contradictory conclusion names or promotion expectations.

## Deliberate limitations

- The direct LONA network freeze was **not** executed here because no exportable LONA OAuth bearer token was available to this standalone runtime.
- The MCP freezer captures SDK-decoded objects, not raw HTTP wire bytes.
- R1 is only awarded when exact original input bytes are explicitly mapped and every report data reference can be bound to those bytes. If LONA does not expose sufficient report→dataset identifiers, the report stays R2/R3.
- SQLite append-only triggers are application-level mutation guards, not cryptographic immutability. External witnessing of the audit-chain head remains required.
- SQLite cannot recompute SHA-256 internally in this package; it validates hash shape and chain ordering while the application computes hashes.
- Production DSR/PBO/CPCV evaluators are intentionally not claimed as implemented by this P0 package.
- `node:sqlite` emits an ExperimentalWarning under Node 22; the test still completes successfully.
