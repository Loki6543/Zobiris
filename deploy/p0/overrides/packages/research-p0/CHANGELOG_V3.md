# P0 v3 hardening changes

This revision implements the required changes from the adversarial review of the original handoff.

## P0 lineage and pre-registration

- Added composite family/candidate/split/result foreign-key lineage.
- Removed writable pre-registration authority; confirmatory proof is derived from audit-chain ordering.
- Research-plan registration must reference a `RESEARCH_PLAN_REGISTERED` event with matching payload hash.
- Confirmatory result events must occur strictly after plan registration.
- Confirmatory results require R1 datasets and primitive evidence.
- Family hypothesis/search-space alignment is checked against the registered plan.
- Evaluation split content hash must equal its registered split hash.

## Selection integrity

- Confirmatory selections must match the pre-registered selection rule, effective-trial function, split, metric, cost model, and candidate universe.
- `trial_count_raw` must equal the stored candidate count.
- Every candidate must have primitive-complete evidence under the selected split/metric/cost before confirmatory selection.
- If a DSR artifact is attached, every candidate must have Sharpe, skew, kurtosis, and observation count populated.

## Validation integrity

- Replaced the overclaiming `MATCH_WITH_EXPLAINED_ROUNDING` with `MATCH_WITH_REGISTERED_NUMERIC_TOLERANCE`.
- Validation eligibility is generated by SQLite.
- Eligible validation requires exact dataset artifact, run config, metric, cost model, split, observation protocol, and execution-model identity.
- Tolerance matches require an explicit tolerance-evidence artifact.
- Full-path verifier compares orders, fills, mark prices, positions, cash, and equity.
- Verifier independently reconstructs account state from fills + marks before comparing engines.

## Promotion/lifecycle

- Family status is derived from append-only lifecycle events instead of a mutable family status field.
- Lifecycle sequence and transition legality are enforced.
- PROMOTED/DEMOTED transitions require corresponding assessment decisions.
- Promotion requires confirmatory evidence, integrity-eligible validation, behavior/integrity artifacts, capital-invariant pass, and human approval.

## Reproducibility/freezer

- Historical R1 classification now requires explicit exact-original-input capture.
- `LONA_ORIGINAL_INPUT_MAP` can map provider data IDs to local source files; the freezer hashes and copies those bytes into the bundle.
- Full-report data IDs are conservatively extracted; if any referenced input cannot be byte-pinned, the report remains R2/R3.
- Provider current-vintage symbol data never upgrades an old report to R1.

## Probe normalization

- Probe dataset is explicitly 1-minute, UTC, continuous 24/7.
- Probe pass/fail does not depend on Sharpe annualization.
- Market execution, commission, slippage, and limit-order semantics are explicit.
- Probe conclusions use exactly the same vocabulary as the verifier/schema.
- Probes never create promotion assessments.
- Added lineage-attack and pre-registration-chain probes.

## Adversarial regression coverage

The self-test now tries to fabricate cross-family lineage, use unrelated/pre-plan audit events, omit confirmatory primitives, use R2 confirmatory data, drift selection metrics, lie about dataset/config identity, reuse another candidate's promotion lineage, jump lifecycle states, and hide a wrong intermediate position behind an unchanged final NAV.
